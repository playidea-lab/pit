# pithub 사업 구성

상세는 [docs/PIT_BUSINESS.md](../../docs/PIT_BUSINESS.md). 여기에는 결정과 그 근거만 남긴다.

## 결정

1. **제품은 원장이고 트윈은 로드맵이다.** 파는 것은 "왜 이렇게 정했는지가 남는다"이며, "디지털 트윈"은 메시지의 앞에 두지 않는다.
2. **첫 사용자는 창업자 개인이고 결제는 없다.** (2026-09-22 수정) 팀 기능과 결제는 함께, 파일럿 판정 뒤에 만든다.
   결제 대신의 강제 장치: **판정일 2026-10-27**을 고정하고, 그 전에는 팀 기능·결제를 만들지 않는다.
   판정 전에 팀 기능을 만드는 것은 잔존이 증명되기 전에 A트랙을 만들던 SEAL의 순서다.
   (원안은 "PI Lab이 3좌석을 실제 결제" — 무료 도그푸딩이 DQ·SEAL에서 두 번 실패했기 때문. 결제를 빼는 대신 판정일을 박는다.)
3. **수익의 순서**: 팀 좌석(첫 수익) → 크리에이터 수수료(공개 트윈 10명 섭외 뒤) → 조직 티어(셀프호스팅). 개인은 무료이며 확산 엔진이다.
4. **공개 범위 4단계**(private · team · friends · public)와 프로젝트별 기본값(없으면 private)을 스키마에 둔다. 트윈은 묻는 사람이 볼 수 있는 결정만큼만 안다 — 경계는 프롬프트가 아니라 행 접근 권한이다.
5. **팔지 않는 것**: 조직의 구성원 비공개 결정 열람, 검증되지 않은 트윈.
6. **JEV**는 public·friends 범위의 확신도 층으로만, 접근 권한이 오고 공개 결정이 쌓인 뒤. 팀 범위 결정은 JEV에 보내지 않는다.

## 근거

- MCP 구조로 한계비용이 ≈ 0 이 되어 무료 개인층이 성립한다 (D-0005).
- claude.ai 커넥터가 실제로 붙어, 코드 밖(PM·기획) 결정을 잡는 유일한 통로가 확보됐다.
- 결정이 사람 사이를 인용하는 그래프는 벤더 메모리(계정 안에 갇힘)가 따라올 수 없는 자리다.

## 사전 선언한 판정 기준

- A1 잔존: 파일럿 28일 중 받은함 연 날 ≥ 14
- A2 신뢰: 재현율 ≥ 60%, 거부 재현율 ≥ 50%, 판정 일치 ≥ 85%
- A3 팀 통증: 남의 결정 열람 3명 합 ≥ 20회
- A5 지불: 3명 중 2명 갱신 의사 + **12주 안에 두 번째 팀 결제**

성공의 정의는 A5의 두 번째 팀 결제 하나다. "개인 도구로는 계속 쓴다"는 성공으로 세지 않는다.

## 접는 기준

A1 미달 → 받은함 없는 축소판 → 그것도 검색 사용 주 1회 미만이면 접는다. 12주 안에 두 번째 팀 결제가 없으면 팀 층 기각.

## 후속 결정 (2026-09-22)

- 두 번째 팀은 온라인에서 찾는다. 전제는 공개 결정 20~30건이 쌓인 공개 페이지. 채널은 결정 링크를 붙일 수 있는 곳(HN, X, GeekNews, 디스콰이엇, MCP 디렉터리). 첫 외부 10명 중 같은 팀 2명 이상이 나오는 곳이 후보.
- 공개 트윈 1호는 창업자. 트윈 = 공개 결정의 집합(프롬프트 페르소나가 아님). 재료는 MCP 기록 + 로컬 백필(세션 27개) + memory 메모 24개 + D-000x. 목표 공개 100건. **남이 묻기 전에 스스로 예측→실제로 적중률을 재고**, 통제군을 못 넘으면 공개하지 않는다.
- JEV API 키 확보 (2026-09-22, 대기열 폐지됨). Fly secret `PITHUB_JEV_API_KEY`에만 둔다. 코드 연결은 공개 결정 100건 뒤.

- 파일럿 판정 시점(2026-10 말 예정)

## 2026-09-22 시점의 판단

비용이 거의 0인 12주 실험으로서 할 만하다. 가장 가능성 높은 결말은 "훌륭한 개인 도구, 평범한 사업"(70%)이고, 두 번째 팀 결제는 30~40%로 본다. 이 숫자를 4주 뒤의 낙관이 덮어쓰지 않도록 여기 적어 둔다.
