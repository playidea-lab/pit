## 2. 주요 논의 내용 (Key Points)

### 시스템 평가

**강점:**
- 문제 정의가 명확함 (기획–코드 정합도 추적)
- 적절한 추상화 (Project/Feature/Checklist)
- 파일 기반 SSOT (Git 친화적)
- 점진적 확장 설계 (R0 → R1 → R2 → R3)

**약점:**
- "문서 10개 + 코드 0줄" 상태
- dogfooding 없이 설계만 존재
- 현재는 "수동 MCP" – LLM이 생성하면 사람이 복붙

### 핵심 철학

> **"문서는 LLM이 쓰고, 사람은 피드백만 한다."**

- 포맷/파일/폴더/ID/인덱싱 → LLM + pit 시스템의 책임
- 사람은 → "이 내용이 지금 맞냐/틀리냐"만 판단
- pit는 "문서 더 쓰게 하는 도구"가 아니라, "이미 LLM과 대화로 쓰고 있는 문서를 덜 귀찮게 정리·추적·연결해주는 도구"

### 문서 통합 결과

| 통합 전 | 통합 후 |
|---------|---------|
| 10개 문서 | 7개 + README |
| 루트에 산재 | docs/ 폴더에 정리 |
| PM/DEV 가이드 분리 | USAGE_GUIDE로 통합 |
| PROJECT_DEFINITION + PRD 중복 | OVERVIEW로 통합 |
